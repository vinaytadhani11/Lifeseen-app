================================================================================
FRIENDS / SCREEN TIME APP FLOW
page_log = 0
================================================================================

Source app     : seenx-reconstructed (package com.app.lifeseen, namespace com.app.seenx)
Current Flutter: Remote Config page_log == 0 opens
                 lib/screens/friends_screen_time/friends_screen_time_screen.dart
                 That screen is only a placeholder. This file is the real flow
                 that folder must follow, the same way lib/screens/whatsapp_mode/
                 holds the page_log = 1 screens.

This document is the user flow only. No code was written from it.
Read from the Android source screens, not from a redesign.

Rule: page_log == 0 is Friends / Screen Time.
      page_log != 0 is the WhatsApp flow and is not part of this file.


================================================================================
1. HOW THE APP CHOOSES THIS FLOW
================================================================================

Splash starts.
  1. Fetch Firebase Remote Config and activate it.
     Fetch fails -> retry the same init. Do not open Home.
  2. Read JSON key "data". The switch is page_log.
  3. Also start RevenueCat getCustomerInfo (async, does not block routing).
  4. If settings.tiktok_key is not empty, init TikTok.
  5. Fetch IP location and save country + city.
     Failure saves "********" for both.

Routing after Remote Config succeeds:

  page_log != 0
      Wait 800ms, then WhatsApp flow.
      This file stops here for that case.

  page_log == 0 AND local documentID is already saved
      Listen to users/{documentID}.
      Listener success -> continue into this flow (section 2).
      Listener failure -> stay on splash. Do not open Home.

  page_log == 0 AND documentID is empty
      Continue into this flow immediately (section 2).

For this flow, RevenueCat customer info does NOT set the screen-time
subscription. Screen-time premium is local only (section 8).
RevenueCat premium flags are used on the WhatsApp branch.


================================================================================
2. FIRST-RUN GATE  (onboarding, then usage access)
================================================================================

After splash, pick the first screen in this order:

  A. isOnboardingFinish == false
        Open Onboarding.
  B. isOnboardingFinish == true AND Usage Access is NOT granted
        Open Time Permissions.
  C. Onboarding done AND Usage Access granted
        Open Home shell. Default tab is Home (middle).

Returning user with both flags already set skips A and B and lands on Home.


--------------------------------------------------------------------------------
2.1 Onboarding  (3 pages, no Skip)
--------------------------------------------------------------------------------

Dark full screen. Three dots. One Continue button. Lottie changes per page.

  Page 0
    Title    : Your Friend's Screen Time
    Subtitle : See in detail how much time your friends spend on which apps
    Lottie   : onboarding_01

  Page 1
    Title    : Focus on What Matters
    Subtitle : Manage your time wisely, reduce distractions, and achieve more with ease
    Lottie   : onboarding_02

  Page 2
    Title    : Establish Your Digital Balance
    Subtitle : Take control of your screen time and create healthier habits
    Lottie   : onboarding_03

Continue on page 0 or 1 only moves to the next page.
Continue on page 2:
  Set isOnboardingFinish = true.
  If Usage Access is already allowed -> Home shell, finish onboarding.
  Else -> Time Permissions, finish onboarding.

There is no Skip button. Back is not a separate exit in this screen.


--------------------------------------------------------------------------------
2.2 Time Permissions
--------------------------------------------------------------------------------

Purpose: block the app until the user grants Usage Access
(PACKAGE_USAGE_STATS / OPSTR_GET_USAGE_STATS). There is no bypass.

Continue:
  If permission is still denied -> open system
  Settings.ACTION_USAGE_ACCESS_SETTINGS.
  Remember that Continue was tapped.
  onResume, only after Continue was tapped, check again.
  Still denied -> open system settings again.
  Granted -> open Home shell and finish this screen.

User who never taps Continue stays on this screen.


================================================================================
3. HOME SHELL  (3 tabs, swipe off)
================================================================================

One shell. ViewPager with user swipe disabled.
Bottom bar switches tabs. Selected icon is white, others are white at 30%.

  Tab 0  Persons     Add Person
  Tab 1  Home        default tab
  Tab 2  Messages    chat list

An incoming intent extra SELECTED_TAB can open a specific tab.
Add Friend on the Home tab jumps to tab 0 (Persons) after the gates pass.

This shell is the root of the logged-in tracker experience.
Child screens (register, premium, settings, chat, statistics) open on top
and return here.


================================================================================
4. SHARED GATE  (premium, then registration)
================================================================================

Used before friend actions. Order is always the same:

  1. Local screen-time subscription is not active
        Open Premium00. Stop. Do not continue the original action.
  2. documentID is empty (user never registered / logged in)
        Open Register. Stop.
  3. Both pass
        Do the original action.

Screens that use this gate:
  Home  -> friend-request bell
  Home  -> Friends' Statistics card
  Home  -> Add Friend card
  Persons tab -> Continue (phone lookup)
  Persons tab -> View friends

Screens that do NOT use this gate:
  Home calendar (needs a saved user id to load a past day)
  Home -> You Statistics (See All) — local usage only
  Home -> Settings
  Messages tab (empty list if not registered; no premium redirect)
  Own screen-time list on Home (hidden until documentID exists)


================================================================================
5. HOME TAB  (tab 1, default)
================================================================================

Top bar
  Left   : friend-request bell. Hidden until
           receivedRequests.size + sentRequests.size > 0.
           Tap (after gate) opens Friendship Status in mode requestsReceived.
           Note: the bell counts sent AND received, but the tap always opens
           the received list, not a mixed list.
  Center : small app logo
  Right  : settings icon -> Settings. No gate.

Body, top to bottom

  1. Add Friend card
       Title    : Add Friend
       Subtitle : Add to track your friends' screen time
       Tap after gate -> switch to Persons tab (tab 0).

  2. Date row
       Label starts as today, format "d MMMM, yyyy" (device locale).
       Calendar button opens a date picker. Max date is today.
       After a date is picked, label becomes "d MMMM yyyy" in Turkish locale.
       The picked day is stored as local-midnight epoch seconds, formatted
       like "1730160000.0" (one decimal).
       Then read users/{my documentID}/screenTimes/{that id}.

       Result:
         Today and the saved day is empty -> show local usage list instead.
         A past day and the saved day is empty -> empty state.
         Day has apps -> show that saved list.
         While loading, show the processing dialog.

  3. Statistics title

  4. You Statistics card
       Title    : You Statistics
       Subtitle : Examine the screen time graph
       Tap -> See All. No premium gate. No registration gate.

  5. Friends' Statistics card
       Title    : Friends' Statistics
       Subtitle : Review the statistical details of your friends
       Tap after gate -> Friendship Status in mode friendsStatics.

  6. Screen Time title
       List of today's apps, or empty text:
       "No screen time available yet; it will appear here once created"

Screen-time list rules
  On open and on resume:
    If Usage Access is missing -> open system Usage Access settings.
    If documentID is empty -> hide the list, show the empty text.
      Do not upload.
    If documentID exists:
      Read today's usage from the device.
      Empty usage -> empty text.
      Usage exists -> upload it, then show the local list.

  Upload path: users/{documentID}/screenTimes/{today midnight id}
  Merge by app name. Also write hourly[24] when the hourly array length is 24.
  Upload failure still shows the local list.

  The list is sorted by duration, longest first.
  Each row is an app name plus hours, minutes, seconds.
  Apps under 10 seconds of foreground time are dropped.

================================================================================
7. REGISTER AND VERIFICATION
================================================================================

Opened when a gated action finds documentID empty.
This is NOT Firebase Phone Auth. The code is a local random 6-digit string.

Register screen
  Back.
  Optional profile photo (gallery). Cropped to a square, saved as JPEG.
  If the photo cannot load: toast and keep the form.
  Country picker + phone field.
  Name field.
  On open, request notification permission on Android 13+.

Continue
  Invalid phone -> field error "Invalid phone number".
  Empty name -> field error "Enter your name".
  Else:
    Generate 6 random digits.
    If notification permission is granted, also post a local notification
    with that same code.
    Copy the code to the clipboard.
    Dialog, not dismissible by tapping outside.
      Title   : Verification Code
      Message : "Enter this exact code on the next screen. It has been copied
                 to your clipboard."
                 then a blank line, then the code.
                 If notifications are off, also:
                 "Notifications are off. Use the code shown above (also copied
                 to clipboard)."
      Continue -> open Verification and close Register.
                  Pass code, full phone, name, and photo uri if any.
      Cancel   -> close the dialog. Stay on Register.

Verification screen
  Back returns to the previous screen (Register is already finished,
  so back leaves verification without creating a user).
  Code field.
  Continue:
    Empty -> toast "Please enter verification code".
    Code does not match the passed code exactly (spaces stripped)
      -> toast "verification failed" (use the code that was shown).
      Do not create a user.
    Match -> save user by phone.

Save user
  Query users where phone == full phone.
  No document:
    Create a new user id.
    Fields: uid, phone, username, photo "", notificationToken "",
            friends [], receivedRequests [], sentRequests [].
    Save documentID and user locally.
    Result: SuccessRegister.
  Document already exists:
    Do not overwrite the name.
    Save that existing user and documentID locally.
    Result: Login.
  Then, if a profile photo was picked, upload it.
  Photo upload success or no photo -> close verification and return
  to whatever opened Register (usually the Home shell still underneath).

Profile photo upload
  Storage path: profile_pictures/{documentID}.jpg
  Then write the download URL into users/{documentID}.photo.


================================================================================
8. PREMIUM  (Premium00, local screen-time subscription)
================================================================================

This is the only paywall on the Friends / Screen Time path in the current
build. RevenueCat purchase code on this screen is commented out.
Premium01–04 and Special Offer belong to the other premium_log path and
are not opened by the gates in sections 4–6.

UI
  Back closes the screen. The original action is not resumed automatically.
  The user must tap the friend action again after purchase.
  Two plans. Weekly is selected by default.
  Plan names come from Remote Config:
    package_id_1_text, fallback "Weekly"
    package_id_2_text, fallback "Monthly"
  Shown prices are fixed strings, not store prices:
    Weekly  $4.99 / week
    Monthly $14.99 / month
  Privacy and Terms open in the browser.
  Continue button animates.

Purchase
  Show processing dialog. Disable Continue.
  Wait 800ms (fake processing).
  Save a local subscription:
    weekly  -> active for 7 days
    monthly -> active for 30 days
    store plan id, plan label, package id, purchase time, expiry time,
    active true, source "local"
  Success toast: "Screen time subscription activated locally."
  Then close Premium00.
  Failure toast and re-enable Continue.

Active check
  No saved subscription -> not active.
  Saved and now >= expiry -> mark active false and treat as expired.
  Expired users see Premium00 again on the next gated tap.

Settings can show status and can reset this local subscription for testing
(section 12).


================================================================================
9. FRIENDSHIP STATUS  (one screen, four modes)
================================================================================

Opened with extra friendshipStatus.

Mode                  Title shown          List source              Row buttons (exact labels)
--------------------- -------------------- ------------------------ ---------------------------
friendsStatics        Friends              my friends[]             See Statistics
requestsReceived      Received Requests    my receivedRequests[]    Approve, Delete
sentRequests          Sent Requests        my sentRequests[]        Delete (this cancels the request)
friends               Friends              my friends[]             Send Message
                      (also friendsMessages uses friends[])

Empty list hides the recycler and shows:

  sentRequests     : There are no sent friend requests yet...
  requestsReceived : There are no friend requests yet...
  friends / other  : You don't have any friends yet...

The screen reloads the list when my user document updates.

Approve (received mode)
  My receivedRequests  -= their uid
  Their sentRequests   -= my uid
  My friends           += their uid
  Their friends        += my uid
  Toast: Friendship request accepted.
  Failure toast: problem accepting the request.

Delete button (received or sent mode) cancels or rejects
  Remove the uid from sentRequests and receivedRequests on BOTH users.
  This covers both "I cancel what I sent" and "I reject what I received".
  Toast: Friendship request rejected.
  Failure toast: failed to decline.

See Statistics (friendsStatics mode)
  Open Friends Statistics for that friend (uid, username, photo)
  and close this list.

Send Message (friends mode)
  Look for a chat whose members contain both uids.
  No chat -> open Chat with chatHistory false (create the room).
  Chat exists -> open Chat with that chat id.
  Then close this list.

Remove friend (friends mode only)
  Long-press a row to reveal Delete and hide Send message.
  Long-press again hides Delete.
  Delete rewrites both users' friends arrays without that uid.
  Toast: removed from friendship.
  The row is removed locally.


================================================================================
10. FRIENDS STATISTICS
================================================================================

Opened with uid, userName, userPhoto.
Missing uid closes the screen immediately.

Header: photo (or default icon) and username.
If username is blank, title falls back to "Friends' Statistics".

Body
  Total time for the selected day.
  24-hour line chart.
  App list for that day, same row style as Home.
  Empty text when that day has no apps.

Date
  Opens on today.
  Label format: "MMMM d, yyyy".
  Today button jumps back to today.
  Calendar max date is today.
  Day id is the same midnight epoch-seconds string as Home ("#.0").

Data
  Read users/{friend uid}/screenTimes/{day id}.
  Document missing -> empty day (apps empty, 24 zeros).
  Read failure -> same empty day.
  Apps come from field "data": list of { name, duration[hours, minutes, seconds] }.
  Chart comes from field "hourly": 24 numbers.
  If hourly is missing but apps exist, the total is spread across 24 hours.
  Total label uses hourly when any hour is > 0, otherwise the sum of app durations.

Special case
  If the opened uid is myself, the selected day is today, and hourly is all
  zeros, replace the chart with a fresh local hourly read.
  The app list still comes from the saved document.

If registered, show those and fill them from the live user:
  friends count, sent count, received count, username, phone, photo.

Actions
  Back.
  Change photo -> gallery, square crop, upload (same storage path as register).
  Edit username -> field becomes editable, icon becomes a tick.

Subscription card (always visible, refreshed on resume)
  No subscription:
    Status: Not subscribed

  Subscription exists:

================================================================================
13. MESSAGES TAB AND CHAT
================================================================================

Messages tab (tab 2)
  If documentID is empty: empty state. Do not listen.
  If registered: listen to chats where members contains my uid.
  Empty result: empty state.
  Each row opens Chat with that user and the existing chat id.
  Delete on a row is a soft delete:
    add my uid into each message's delete array,
    and into the recent message delete array.
    The room document stays. The row is removed from my list.

Chat
  Header: friend photo, friend name, back, and a statistics button.
  Statistics opens Friends Statistics for that friend. Chat stays in the back
  stack (this path does not finish Chat).

  Existing chat: listen to chats/{chatId}/messages.
  New chat (chatHistory false):
    chat id = the two uids sorted and joined with "_".
    Example: uidA_uidB with the alphabetically smaller uid first.
    Create chats/{chatId} with members, both user snapshots, empty recent text.
    Then listen.

  Composer: Send stays disabled while the text is blank.
  Send writes a text message:
    senderId = my documentID
    messageType = "text"
    text, timestamp
  On success, clear the field and keep the list scrolled to the latest message.

Friends can message only after they are connected, because Send message
lives on the friends list. The Messages tab itself does not re-check premium.

================================================================================
15. WHAT GETS SAVED
================================================================================

Local prefs used by this flow
  isOnboardingFinish
  documentID
  userData (uid, phone, username, photo, friends, receivedRequests, sentRequests)
  screenTimeSubscription (plan, dates, active)
  country, city (from IP, splash)

Server collections used by this flow
  users/{uid}
    uid, phone, username, photo, notificationToken
    friends[]
    receivedRequests[]
    sentRequests[]
    screenTimes/{midnightEpoch.0}
      data[]   = { name, duration[h, m, s] }
      hourly[] = 24 numbers (minutes)

  chats/{uidA_uidB}
    members[]
    config (both users)
    recent message
    messages/{id}
      senderId, messageType, text, timestamp, delete[]

  Storage
    profile_pictures/{uid}.jpg

Usage collection (device)
  Known social apps if installed (Facebook, YouTube, WhatsApp, Instagram,
  TikTok, Telegram, Snapchat, and the rest of the fixed package list)
  plus installed non-system apps whose package starts with "com.".
  Cache that package map for 1 hour.
  Query INTERVAL_DAILY from local midnight to now.
  Keep packages in the target set with foreground time >= 10 seconds.
  Duration stored as [hours, minutes, seconds].

16. FULL HAPPY PATH  (two people)
================================================================================

Phone A and Phone B both have page_log = 0.

  1. Each phone: Splash -> Onboarding (3 Continues) -> Usage Access -> Home.
  2. Each phone taps a gated control (Add Friend, Friends' Statistics, or
     Persons Continue).
  3. Premium00 -> pick Weekly or Monthly -> Continue -> local sub saved.
  4. Register -> country, phone, name, optional photo -> Continue.
  5. Dialog shows the random 6-digit code (copied to clipboard).
  6. Verification -> enter that exact code -> user document created.
  7. Home shows that phone's own app list and uploads today's screen time.
  8. Phone A, Persons tab, enters Phone B's number -> Continue.
  9. Dialog "You Are Not Friends" -> OK.
     A.sentRequests += B, B.receivedRequests += A.
 10. Phone B sees the bell (or Settings -> Incoming requests).
     Opens Received Requests -> Accept.
     Both friends[] gain the other uid. Request arrays lose that pair.
 11. Phone A opens Friends' Statistics, picks Phone B, taps Statics.
     Sees B's uploaded apps, total time, and 24-hour chart.
 12. Phone B can open A's statistics the same way.
 13. From the Friends list, Send message.
     Chat id is the two uids sorted with "_".
     Text sends both ways. Messages tab lists the room.


================================================================================
17. EDGE CASES
================================================================================

  Wrong verification code
    Stay on Verification. No user is created.

  Add my own number
    ownProfile dialog. No request is written.

  Number not registered
    User Not Found + share sheet. No request is written.

  Already friends
    Jump straight to the friends statistics list.

  Request already sent
    Jump to Sent Requests. Decline there cancels it on both sides.

  Request already received
    Jump to Received Requests. Accept or Decline.

  Premium expired or reset in Settings
    Next gated tap opens Premium00 again.
    Home screen-time list and See All still work without premium.

  Not registered
    Home screen-time list stays empty even if Usage Access is on.
    Messages tab stays empty.
    Settings hides profile and friend rows.

  Usage Access revoked later
    Home and See All open system Usage Access settings again.

  Calendar on a past day with no upload
    Empty state. Do not invent local usage for a past day.

  Calendar on today with an empty server doc
    Fall back to the local usage list.

  Upload fails
    Still show the local list.

  Splash user listener fails while documentID is set
    Remain on splash. Do not open Home.

  Log out or delete account
    Clear prefs, including onboarding, documentID, and the local subscription.
    Next launch is a fresh splash, so onboarding shows again.

  Friend statistics for myself with an empty hourly array today
    Chart uses a live local hourly read.
